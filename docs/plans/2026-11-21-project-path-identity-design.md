# 项目路径身份与跨项目关联设计

> 日期：2026-11-21
> 状态：待评审
> 范围：worklog / conclusion 的项目模型、MCP 入参、前端树与筛选、数据迁移

## 1. 背景

现状的项目只是自由文本名称：

- 工作记录：`WorklogProject.name` 由 AI 在 `record_work` 时传入
- 结论卡：`Conclusion.project` 是字符串

由此产生三个问题：

1. **同一项目多个名称**（如「资源加工平台」与「rppweb」都指向 `D:\xunfei\资源加工平台`）。
2. **改名断链**：结论卡存的是名称字符串，`rename_project` 不会更新历史卡。
3. **跨项目需求无法表达**：一个需求常同时改多个业务域（资源加工平台 + 题库），现有模型只能记一个项目。

实际目录结构（2026-11-21 核实）：

```
D:\xunfei\资源加工平台\        ← 用户心智中的项目（业务域，本身无 .git）
  ├─ 前端\rpp-web\.git
  ├─ 后端\crowdsourced-new\.git
  ├─ ...（共 10 个仓）
  └─ 搜题平台\                ← 独立记录的另一个项目
       ├─ 前端\...\.git
       └─ 后端\...\.git
D:\xunfei\组卷\    ← 3 个仓
D:\xunfei\题库\    ← 9 个仓
```

因此：**项目是业务域，不是 git 仓**；一个项目可对应多个本地路径。

## 2. 目标与非目标

### 目标

- 项目有稳定身份，改名不影响历史记录。
- 同一项目可绑定一个或多个本地路径，用于判定记录归属。
- 跨项目需求可标注关联项目，且不破坏版本语义。
- 现有数据可平滑迁移，不丢记录。

### 非目标（YAGNI）

- 不做文件系统扫描、不做目录自动发现。
- 不做多用户/权限。
- 不把路径当作项目的唯一身份（路径会移动）。
- 不把结论卡的归属改为按路径判定（结论卡以会话为锚）。

## 3. 概念模型

| 概念 | 定义 |
|---|---|
| **Project** | 业务域。稳定身份 `id`，显示名 `name`，归属路径 `paths[]` |
| **归属** | 某条工作记录算哪个项目，由 `sourcePath` 与项目 `paths` 的最长前缀匹配决定 |
| **关联项目** | 一条记录/结论同时涉及的其他项目（只有关系，不复制内容） |

### 3.1 两个模块的定位差异

| | 工作记录 | 结论卡 |
|---|---|---|
| 核心用途 | 按版本回溯"改了什么" | 实时更新会话结论、保留判断演进 |
| 锚点 | 项目 + 版本 | 会话（一对话一卡） |
| 路径的作用 | **参与归属判定** | **只用于展示与筛选，不参与归属** |
| 关联项目 | 表达"本次改动还涉及哪些项目" | 表达"这个判断涉及哪些工程" |

## 4. 数据模型

### 4.1 工作记录（worklog.json）

```ts
interface WorklogProject {
  id: string;                 // 新增：稳定身份，p_xxx
  name: string;               // 显示名，仍要求唯一（AI 入参用名称）
  paths?: string[];           // 新增：归一化绝对路径，可多个；空 = 未绑定
  createdAt: number;
  versions: WorklogVersion[]; // 不变
}

interface WorklogEntry {
  // 现有字段不变
  sourcePath?: string;          // 新增：记录时的 cwd（保留原始大小写，匹配时临时归一化）
  relatedProjects?: string[];   // 新增：关联项目名称快照（展示用，改名时级联）
  relatedProjectIds?: string[]; // 新增：关联项目稳定引用（判定用）
}
```

`WorklogVersion` 与版本内的 `entries` 结构不变。

### 4.2 结论卡（conclusions.json）

```ts
interface Conclusion {
  // 现有字段不变（含卡片级 conversationId / conversationName）
  projectId?: string;          // 新增：项目稳定引用
  project?: string;            // 保留：名称快照，用于项目被删除后的兜底展示
  relatedProjectIds?: string[]; // 新增：关联项目
  revisions: ConclusionRevision[]; // 不变
}
```

- 结论卡**不新增 paths**，`revision.source.cwd` 仍保留为来源证据。
- 一会话一卡、卡片级 `conversationId` 归属规则不变。

### 4.3 项目表归属

项目表的**唯一事实来源是 worklog 的 `projects`**。结论卡只存 `projectId` 与名称快照，不维护第二份项目表。

- 展示结论卡时：优先用名称快照；需要最新名称时由接口解析 `projectId`。
- 项目被删除：结论卡保留名称快照，展示为「项目已删除」，不级联删除结论卡。

## 5. 归属与关联规则

### 5.1 工作记录的路径归属

记录时按以下顺序：

```
1. 取 cwd（或 MCP 显式传入的 projectPath）
2. 归一化：realpath → 统一斜杠 → Windows 转小写 → 去尾分隔符
3. 与所有已绑定项目的 paths 做最长前缀匹配（按路径分隔符边界）
4. 命中 → 主项目 = 该项目
5. 未命中 → 主项目 = AI 传入的 project 名称（沿用现状），sourcePath 仍记录
```

归一化后的值**只用于比较**；项目 `paths` 与记录 `sourcePath` 都保存用户输入的原始写法，展示时不转小写、不改斜杠。

边界规则：

- 前缀匹配必须在**分隔符边界**上：`D:\xunfei\资源加工平台` 不得匹配 `D:\xunfei\资源加工平台2`。
- 同一路径只允许绑定一个项目；冲突时后绑定操作被拒绝。
- 路径不存在不阻止记录，只在页面标「路径失效」。

### 5.2 为什么不做 .git 自动推断

实测 `资源加工平台` 下有 10 个 git 仓、`题库` 下 9 个。在 `...\前端\rpp-web` 里取 `.git` 会得到 `rpp-web`，与用户心智的「资源加工平台」粒度不符。

`.git` / 项目标志物（`pom.xml`、`package.json` 等）只用于**绑定建议**：页面提示「该路径疑似属于 X」，由用户确认后才写入。

### 5.3 关联项目

- MCP 入参使用**名称**（`relatedProjects: string[]`），AI 友好。
- 服务端写入时同时保存 `relatedProjectIds`（稳定引用）与 `relatedProjects`（名称快照）。
- 解析规则：名称精确匹配现有项目；不存在则报错并返回现有项目名列表，不自动创建（避免拼错裂树）。
- `rename_project` 时同时更新两侧的名称快照（工作记录条目与结论卡）。
- 关联项目**不带版本**。UI 显示为「同时涉及：题库」，不伪造版本归属。
- 关联项目不出现在树的其他位置，只在主项目条目详情中展示。

### 5.4 结论卡

- 主项目由 AI 传名称，服务端解析为 `projectId`；路径不参与判定。
- **项目不存在时**：不报错、不自动创建，保留名称快照，`projectId` 留空。结论卡常早于工程记录出现，阻塞记录会破坏"实时更新会话结论"的主线；后续可在页面把该卡关联到已有项目。
- 关联项目仍按 5.3 严格校验（显式声明的关系不应臆造）。
- 项目改名：名称快照由 `rename_project` 同步更新（结论卡与工作记录两侧）。

## 6. MCP 变更

| 工具 | 变更 |
|---|---|
| `record_work` | 新增 `relatedProjects?: string[]`；返回结果附「已关联项目」 |
| `record_conclusion` | 新增 `relatedProjects?: string[]` |
| `query_work` | 结果每条附 `关联项目: x, y`（若有）；新增 `relatedProject?: string` 过滤 |
| `query_conclusions` | 结果附关联项目；支持按关联项目过滤 |
| `list_projects` | 输出 `id`、`name`、`paths`；未绑定标注 |
| `rename_project` | 级联更新结论卡名称快照 |

路径绑定与解绑**不提供 MCP 工具**，只允许页面操作，避免 AI 误绑。

## 7. 前端

### 7.1 树

- 项目行：名称 + 路径尾段（如 `…\xunfei\资源加工平台`）。
- 未绑定：显示「未绑定路径」弱化标记。
- 路径失效：红色标记 + 悬停提示。
- 层级仍为「项目 → 版本」，不新增目录层级。

### 7.2 项目操作

项目右键菜单新增：

- 绑定路径 / 修改路径（支持多行，一行一个）
- 解除绑定
- 重命名（现有）

### 7.3 记录详情

- 展开后显示「关联项目」标签，点击可跳转到对应项目。
- 未绑定主项目时显示来源路径与「绑定到项目」快捷入口。

### 7.4 筛选

- 工作记录：新增「关联项目」筛选（多选），与阶段筛选并列。
- 结论卡：同样支持关联项目筛选。
- 搜索关键字暂不扩展到路径（避免与"内容搜索"语义混淆）。

## 8. 迁移

一次性迁移，幂等，启动时或首次写操作时执行：

1. **补 id**：无 `id` 的项目生成 `p_` + 短随机 id。
2. **结论卡绑定**：按 `project` 名称精确匹配 worklog 项目，写入 `projectId`；匹配不上只保留名称快照。
3. **路径建议**：
   - 对每个未绑定项目，检查 `D:\xunfei\<name>`、`D:\Study\<name>` 是否存在，存在则在页面显示「建议绑定」，用户确认后写入。
   - 不自动写入，不扫描其他目录。
4. **历史 cwd**：结论卡已有的 `source.cwd` 汇总为绑定建议，展示在项目设置中。
5. **源数据备份**：迁移前快照 `worklog-backups/` 与 `conclusion-backups/`。

迁移不修改任何记录的归属（历史记录仍挂原项目名）。

## 9. 错误与边界

| 场景 | 处理 |
|---|---|
| 同名项目已存在 | 拒绝创建（沿用现状） |
| 路径已绑定其他项目 | 拒绝绑定，提示占用方 |
| 路径被移动/删除 | 页面标失效；记录不受影响 |
| 关联项目名不存在 | 报错并返回现有项目名，不自动创建 |
| 项目被删除 | 结论卡保留名称快照，标「项目已删除」 |
| cwd 命中黑名单（home、盘符根、Temp） | 不参与匹配，只记 sourcePath |
| Windows 大小写/斜杠差异 | 归一化后比较，避免同目录裂成两个节点 |

## 10. 测试

- 纯函数：路径归一化、分隔符边界前缀匹配、最长匹配优先级。
- 服务层：按路径归属、未命中回落名称、关联项目解析失败、改名级联。
- 迁移：无 id 项目补 id；结论卡按名称绑定；幂等重跑。
- MCP：`relatedProjects` 写入与查询输出、`list_projects` 路径输出。
- 前端：树显示路径尾段/未绑定/失效、关联项目筛选、项目菜单绑定路径。
- 回归：现有 211 后端 / 137 前端测试全绿。

## 11. 风险

| 风险 | 缓解 |
|---|---|
| MCP cwd 不可靠 | 只作候选；未命中按名称记录，sourcePath 留痕 |
| 结论卡名称快照与项目名不一致 | 改名级联 + 展示时优先解析 id |
| 项目表只在 worklog 侧，结论卡跨模块依赖 | 只读引用；项目删除不级联；接口返回兜底名称 |
| 路径绑定遗漏导致归属错误 | 未绑定在树上显式标注，不静默 |

## 12. 实施顺序（概要）

1. shared 类型与迁移工具（补 id、归一化、匹配纯函数）
2. Worklog 服务：归属、关联项目、项目路径 CRUD
3. Conclusion 服务：projectId、关联项目、改名级联
4. MCP 工具与描述
5. 前端树、项目菜单、详情标签、筛选
6. 迁移与全量测试
