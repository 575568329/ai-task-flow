## 一、背景与目标

在 ai-task-flow 看板中新增"思维导图"模块，支持新建、编辑、保存、导出。

**MVP 目标（含验收标准）**
- 新建/编辑/保存思维导图（增删改节点、拖拽、折叠、同级排序）
- 自动布局（dagre）+ 导出 PNG/SVG
- **自动保存**（debounce 2s）+ 离开拦截 + 保存失败提示
- 列表页管理（新建/打开/删除/复制/重命名/搜索）+ 空状态引导
- 视觉融入 shadcn 主题，交互丝滑（<100ms 响应、60fps 动画）
- **验收**：建图→编辑→自动保存→刷新数据不丢→导出 PNG 分享，全流程闭环

**非目标（后续）**：富文本 / AI 扩写 / 多人协作 / XMind 互通 / 与 task 联动功能（仅留演进方向）

## 四、数据模型设计

### 4.1 shared 类型（`shared/src/types/mindmap.ts`）—— 🔴 不依赖 @xyflow/react

**核心决策**：shared 是零依赖纯类型包（backend/cli/extension 共用）。`nodes/edges` 在 shared 里**手写结构同构 interface**，不 `import '@xyflow/react'`；前端 `Node<MindmapNodeData>` 靠 TS 结构类型天然兼容（RF 的 Node 字段是其子集）。

```ts
export type BranchKey = 'blue'|'teal'|'emerald'|'amber'|'orange'|'rose'|'violet'|'indigo';

/** 节点业务数据 */
export interface MindmapNodeData {
  label: string;
  note?: string;           // 节点备注（纯文本，MVP 新增）
  expanded?: boolean;      // 默认 true
  branch?: BranchKey;      // 所属分支色
  level?: number;          // 0=根
}

/** 结构同构于 @xyflow/react 的 Node<MindmapNodeData>，shared 不依赖 xyflow */
export interface MindmapFlowNode {
  id: string;
  type?: string | null;
  position: { x: number; y: number };
  data: MindmapNodeData;
  width?: number; height?: number;
  selected?: boolean; hidden?: boolean; dragging?: boolean;
}

export interface MindmapFlowEdge {
  id: string;
  source: string; target: string;
  type?: string | null;
  sourceHandle?: string | null; targetHandle?: string | null;
  data?: { branch?: BranchKey };
  animated?: boolean; hidden?: boolean;
}

export interface MindmapDocDTO {
  id: string;
  title: string;
  version: number;          // 🔴 乐观锁版本号
  nodeCount: number;        // 🔴 冗余字段，list 不解析 nodes
  nodes: MindmapFlowNode[];
  edges: MindmapFlowEdge[];
  viewport?: { x: number; y: number; zoom: number };
  createdAt: string;        // ISO
  updatedAt: string;        // ISO
}

export interface MindmapMetaDTO {
  id: string; title: string; nodeCount: number;
  createdAt: string; updatedAt: string;
}

export interface MindmapCreateDTO { title?: string; }
export interface MindmapUpdateDTO {
  title?: string;
  nodes?: MindmapFlowNode[];
  edges?: MindmapFlowEdge[];
  viewport?: { x: number; y: number; zoom: number };
  expectedVersion?: number; // 🔴 乐观锁：客户端持有版本
}
export interface MindmapListResponse { items: MindmapMetaDTO[]; total: number; }
```

**上限常量**（提取魔法值）：
```ts
export const MAX_TITLE_LENGTH = 100;
export const MAX_NODES_PER_DOC = 2000;   // 超 RF 放心区
export const MAX_DOCS = 500;
export const MAX_DOC_BYTES = 2 * 1024 * 1024;
```

> 记得在 `shared/src/index.ts` 加 `export * from './types/mindmap.js'`。

### 4.2 后端聚合根 —— 🔴 守存储不变量（不校验布局）

```ts
// domain/mindmap/entities/MindmapDoc.ts
class MindmapDoc {
  readonly id: string;
  title: string;
  version: number;
  nodeCount: number;
  private nodes: MindmapFlowNode[];
  private edges: MindmapFlowEdge[];
  viewport: {x,y,zoom} | null;
  readonly createdAt: Date;
  updatedAt: Date;

  static create(title?: string): MindmapDoc;        // UUID + 默认根节点 + version=0
  rename(title: string): void;                       // trim + 非空 + 长度上限
  applyUpdate(dto: MindmapUpdateDTO): void;          // 见下，守不变量 + version++
  private updateGraph(nodes, edges): void;           // 🔴 校验：id 非空唯一、edge 引用完整、上限
  get isRootOnly(): boolean;
  toJSON(): MindmapDocDTO;
  static fromJSON(dto): MindmapDoc;
}
```

**`updateGraph` 守的不变量**（与渲染框架无关，后端必须守）：
- `node.id` 非空、唯一
- `edge.source/target` 必须在 nodes 中存在
- `nodes.length <= MAX_NODES_PER_DOC`
- 不校验 position/measured/handleBounds（前端职责）

## 五、后端 API 设计

PATCH 风格（与 vocab 一致），前缀 `/api/mindmaps`，错误体 `{ error: string }`，无 envelope。

| 方法 | 路径 | 说明 | 响应 |
|------|------|------|------|
| GET | `/api/mindmaps` | 列表（仅 meta，不解析 nodes） | `MindmapListResponse` |
| POST | `/api/mindmaps` | 新建 | `MindmapDocDTO`（201） |
| GET | `/api/mindmaps/:id` | 获取完整文档 | `MindmapDocDTO` |
| **PATCH** | `/api/mindmaps/:id` | 部分更新（带 `If-Match` 乐观锁） | `MindmapDocDTO` |
| DELETE | `/api/mindmaps/:id` | 硬删 | 204 |
| POST | `/api/mindmaps/:id/duplicate` | 复制（新 id/title+" 副本"/version=0） | `MindmapDocDTO`（201） |

**乐观锁**：PATCH 请求 `If-Match: <version>` 或 body `expectedVersion`；后端比对不一致返 **409**，前端提示"已被他处修改，请刷新"。

**校验上限**：超限返 400（标题/节点数/文档数）或 413（单文档字节）。

**类型化错误**（照 vocab）：`MindmapNotFoundError`→404、`MindmapValidationError`→400/413、`MindmapConflictError`→409、`MindmapLimitExceededError`→400。

**日志**：`new FileLogger('mindmap')`，service 关键操作（create/update/delete/duplicate）+ IO 异常落文件。

**EventBus/SSE**：MVP **不接入**（单用户单标签为主）；文档声明留接入点：未来 `MindmapUpdated` 事件 + 复用 `/api/events` SSE。

**保存策略**：前端全量 PATCH（整个 nodes/edges），MVP 不做节点级 diff（YAGNI）。

## 六、存储设计

```ts
// backend/src/config/dataDir.ts
export function mindmapsFilePath(dataDir?: string): string {
  return path.join(resolveDataDir(dataDir), 'mindmaps.json');
}
```

存储结构（单文件多文档，**nodeCount 冗余**）：
```json
{ "documents": [ { "id":..., "version":3, "nodeCount":42, "nodes":[...], "edges":[...], ... } ] }
```

**🔴 原子写**（修复 saveAll 写崩溃丢数据）：`writeFile(tmp) → fs.rename(tmp, target)`。建议抽 `atomicWriteFile()` 工具，vocab 等模块一并受益。

**并发**：沿用 `withWriteLock` 串行化 loadAll→改→saveAll。

**演进路径**（注释）：文档数/体积增长后，拆为 `mindmaps/<id>.json` + `mindmaps/index.json`（仅 meta），PUT 只读写单文件。

### 7.2 🔴 keep-alive 懒挂载（解决画布常驻）

项目 `App.tsx` 所有视图 keep-alive 常驻。React Flow 不能跟着常驻，策略：

- `MindmapView` 内部读 `useUIStore.activeView`；**仅当 `activeView==='mindmap'` 且有打开文档时**才挂载 `<MindmapEditor>`，否则卸载。
- 卸载前把当前 `nodes/edges/viewport` 暂存进 `mindmapStore.draft`；重新挂载时从 draft 重建画布。
- **键盘监听绑在画布容器 `<div tabIndex={-1}>` 上**，不绑 window（避免切到看板仍触发 Tab 新建）。
- 导出 PNG 前校验画布已挂载且非 hidden（hidden 下尺寸为 0，bounds 脏）。

### 7.3 🔴 Store 职责切分 + dirty 桥（受控模式）

**项目 `mindmapStore` 只管文档级状态**（列表、当前 meta、draft、isDirty、saveStatus）；**nodes/edges 不进项目 store**，由 `MindmapEditor` 本地 `useState` 持有（受控模式）。

```tsx
// MindmapEditor（在 ReactFlowProvider 内）
const [nodes, setNodes] = useState<Node<MindmapNodeData>[]>(initial);
const [edges, setEdges] = useState<Edge[]>(initial);

const onNodesChange = useCallback((chs: NodeChange[]) => {
  setNodes(nds => applyNodeChanges(chs, nds));
  markDirtyDebounced();                 // 🔴 桥到项目 store（debounce，不每帧）
}, [markDirtyDebounced]);
// onEdgesChange 同理

// 保存（debounce 2s 自动 / 手动 Ctrl+S）：序列化本地 nodes/edges → PATCH
const save = useCallback(() => {
  mindmapApi.update(id, { nodes, edges, viewport, expectedVersion: current.version });
}, [nodes, edges, ...]);
```

- RF 的拖拽重渲染由 RF 内部 `useStore` selector 优化；项目 store 只收 dirty 信号 → **性能与切分都成立**。
- `markDirtyDebounced`：diff position 真变化才置 dirty（点选不误触发）。

### 7.4 视图接入（2 处）

- `App.tsx`：`VIEWS` map 加 `mindmap: MindmapView`

## 八、视觉样式设计

### 8.1 设计基调
XMind 2025 / MindNode 精致卡片派：去粗描边、贝塞尔弧线、分支着色、大留白、柔和漂浮阴影。只有根节点是"重色焦点"。

### 8.2 🔴 React Flow 主题接入（OKLCH，不是 HSL）

**项目 `index.css` 用 OKLCH**（`--card: oklch(1 0 0)`）。**直接用 `var(--card)`，不要 `hsl()` 包裹**，否则非法 CSS 被丢弃。

`index.css` 的 `@import` 顺序（必须在 `@theme`/`:root` 之前）：
```css
@import "tailwindcss";
@import "tw-animate-css";
@import "@xyflow/react/dist/base.css";   /* 只含结构，不含默认蓝主题 */
@import "./styles/animations.css";
```

```css
.react-flow {
  /* 节点兜底（自定义节点会覆盖） */
  --xy-node-background-color-default: var(--card);
  --xy-node-color-default: var(--card-foreground);
  --xy-node-border-default: var(--border);
  --xy-node-boxshadow-selected-default: 0 0 0 2px var(--ring);
  /* 连线兜底（分支色在 BranchEdge 里覆盖） */
  --xy-edge-stroke-default: color-mix(in oklch, var(--muted-foreground) 50%, transparent);
  --xy-edge-stroke-width-default: 2;
  --xy-edge-stroke-selected-default: var(--ring);
  --xy-connectionline-stroke-default: var(--ring);
  /* 背景/框选/Controls/MiniMap 全部映射到 shadcn token */
  --xy-background-pattern-dots-color-default: var(--border);
  --xy-selection-background-color-default: color-mix(in oklch, var(--ring) 15%, transparent);
  --xy-controls-button-background-color-default: var(--background);
  --xy-controls-button-background-color-hover-default: var(--accent);
  --xy-controls-button-color-default: var(--foreground);
  --xy-controls-button-border-color-default: var(--border);
  --xy-minimap-background-color-default: var(--card);
}
/* 深色模式自动跟随 .dark（变量引用同一 token） */

/* 选中态用 ring 替代默认蓝光 */
.react-flow__node.selected { box-shadow: none; }
.react-flow__node.selected .mm-card { outline: 2px solid var(--ring); outline-offset: 2px; }
/* 思维导图隐藏默认 handle，hover/选中显示 */
.react-flow__handle { opacity: 0; transition: opacity .15s; }
.react-flow__node:hover .react-flow__handle,
.react-flow__node.selected .react-flow__handle { opacity: 1; }
```

> Tailwind preflight 会"裸化" Controls 按钮，需在 `.react-flow__controls-button` 补 `background-color`（实测确认）。

### 8.4 节点层级规范（Tailwind className 草稿）

| 层级 | className |
|------|-----------|
| 根 | `rounded-xl px-5 py-3 text-lg font-bold bg-primary text-primary-foreground shadow-lg ring-1 ring-primary/20` |
| 一级分支 | `rounded-lg px-4 py-2.5 text-sm font-semibold bg-[var(--branch-bg)] text-[var(--branch-fg)] border border-[var(--branch-line)]/30 shadow-sm`（左 4px 竖条） |
| 叶子 | `rounded-md px-3 py-1.5 text-[13px] font-medium bg-card text-card-foreground border border-border hover:bg-accent/40` |

交互态：hover `-translate-y-px shadow-md`；编辑态 input `ring-2 ring-ring`；拖拽态 `.dragging` 加重阴影 + `scale(1.02)`。

### 8.5 连线规范
- 类型 `default`（贝塞尔，思维导图归属语义）；线宽随层级 2.5→1.5px；**无箭头**；分支色 `stroke-opacity` 用 `color-mix`。
- 🔴 **聚焦效果走 CSS 属性选择器**（不用 setEdges，否则破 memo）：`.react-flow[data-hover-branch="blue"] .react-flow__edge:not([data-branch="blue"]) { opacity:.25 }`。P2 实现。

### 8.6 画布/间距/字体
- `<Background variant="dots" gap={18} size={1.5} />`；dagre `rankdir:'LR', ranksep:110, nodesep:28, marginx:40, marginy:40`。
- 系统字体栈（中文加 `PingFang SC`/微软雅黑）；字号 18/15/13px。
- 节点尺寸**依赖 RF 内置 ResizeObserver，禁止手写 `node.width/height`**；统一尺寸用 `updateNodeInternals([id])`。

### 9.3 新手易忽略的细节
1. 新建节点后必须自动 focus + 光标定位到末尾。
2. 入场动画用 scale/opacity（**别动 `transform.translate`**）。
3. input 必须 `className="nodrag nopan"`。
4. `connectionLineType` 与 edge type 一致（都 bezier）。
5. 同级排序改 tree children 顺序，dagre 按序布局。

## 十、性能保障

**规模评估**：真实思维导图平均 ~31 节点，RF 放心区 <200，覆盖 99%。**不用担心卡顿。**

**性能红线（必须做）**：
- `nodeTypes/edgeTypes` 定义在**组件外**或 `useMemo`
- 自定义节点/边 `React.memo`
- 传给节点的 `data` **稳定引用**（绝不内联 `{{}}`）
- `<ReactFlow>` 的函数 prop 用 `useCallback`，对象 prop 用 `useMemo`
- 不为取 selected 去 `useNodes()` 再 filter（单独存字段）
- 升级到 v12.11.3+

**建议**：折叠子树用 `hidden`（比视口剔除更可控）；选中态走 CSS；`onlyRenderVisibleElements` 保持默认 false。

**keep-alive 注意**：画布懒挂载（见 7.2）避免多实例累积。

## 十一、产品体验与演进

### 11.1 空状态与首次引导（MVP）
- 列表页空状态：价值文案 + "新建思维导图"主按钮 + 一键载入的**示例文档**（如"项目拆解"模板）。
- 编辑器首次进入：根节点旁浮**气泡提示**（"Tab 加子节点，Enter 加同级"），点一次消失。
- `?` 呼出快捷键面板。

### 11.2 删除策略（MVP）
- **硬删 + 前端"撤销删除"toast（5s 内可恢复 = 重新创建）**；与 vocab 一致，不引入软删复杂度。
- 列表页删除按钮与复制按钮拉开间距，防误触。
- P1 考虑软删回收站（`del_status` 字段）。

### 11.3 自动保存与防丢（MVP）
- debounce 2s 自动保存（D5）；dirty 时 `beforeunload` 拦截确认。
- 保存失败：角标变红 + toast 重试。
- P1：localStorage 兜底缓存最近编辑。

### 11.4 与 task 看板联动（演进方向，MVP 不做）
ai-task-flow 是"任务编排看板"，思维导图应是 task 的**前序工序**。演进路线：
- P1：思维导图**导出 Markdown 大纲**（嵌套列表）。
- P2：task 看板**从 Markdown 导入**生成 task；节点右键"发送到看板"。
- 形成"梳理→拆解→转 task→执行"闭环。

## 十二、任务拆解

### 阶段 1：后端骨架 + API（P0，~1.5 天）
- shared 类型（结构同构，不依赖 xyflow）+ 上限常量
- domain（MindmapDoc 聚合根，守不变量）+ repositories 接口
- application（MindmapService + 类型化错误 + FileLogger）
- infrastructure（JsonMindmapRepository + **atomicWriteFile** + nodeCount 冗余）
- routes（PATCH + 乐观锁 409 + 校验上限）
- 装配（http-server.ts / server.ts 两处签名 + dataDir helper）
- **单测**（MindmapDoc 不变量、MindmapService CRUD、乐观锁冲突）+ curl 测试

### 阶段 2：画布可用 + 视觉（P0，~2.5 天）
- 引入 @xyflow/react（v12.11.3）+ base.css + **OKLCH 主题映射**（spike 验证深浅色）
- 受控模式 MindmapEditor + dirty 桥（spike 验证）
- MindmapNode（memo，三层级）+ BranchEdge（memo，bezier 分支色）+ 8 色 OKLCH 色板
- 文本编辑 + note popover + dots 背景 + Controls/MiniMap
- keep-alive 懒挂载（spike 验证键盘/内存/导出）
- 自动保存（debounce 2s）+ 乐观锁 409 处理 + beforeunload + 保存状态角标

### 阶段 3：思维导图体验（P0，~2 天）
- dagre 自动布局（LR，先瞬移）+ Toolbar
- 折叠/展开子树（hidden + 重排）
- 快捷键（Tab/Enter/Delete/方向键）+ 首次气泡 + `?` 面板
- 同级拖拽排序
- 撤销/重做（快照栈，按编辑事务）
- 节点增删 CSS 动效

### 阶段 4：闭环 + 增强（P0/P1，~1.5 天）
- 导出 PNG/SVG（html-to-image 锁版本，深色模式处理）
- 列表页（搜索/就地重命名/空状态/示例文档/删除撤销 toast）
- 只读大纲侧栏
- **P1**：布局/折叠 d3-timer 平滑过渡、对齐线、localStorage 兜底、查找替换

> 总计 MVP 约 7.5 天。三个 spike（OKLCH 主题、受控 dirty 桥、keep-alive）放阶段 2 初先验。

## 十三、决策点定稿

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| D1 | 布局方向 | **MVP 单向(LR)**，数据结构预留 `direction` 字段 | dagre 一行配置；双向 P2 |
| D2 | 编辑态 Enter | **确认+新建同级**（幕布风格），Shift+Enter 换行 | 重度编辑流畅；配首次气泡引导 |
| D3 | 撤销/重做 | **进 MVP**，~1.5 天 | 高频编辑刚需 |
| D4 | 节点富文本 | **MVP 纯文本 label + note**（轻量备注 popover） | 富文本 P2；note 比 RTF 更基础 |
| D5 | 保存策略 | **手动 + debounce 2s 自动保存** | 防丢失底线，对齐 v2 建议 |
| D6 | 自动布局动画 | **功能 MVP，平滑过渡 P1**（d3-timer） | 先瞬移可用，动画一次做好复用 |
| D7 | AI/分组 | **MVP 不做**；平铺列表+搜索 | — |
| D8 | 删除策略 | **MVP 硬删 + 撤销 toast(5s)**；P1 软删回收站 | 与 vocab 一致，防误删 |
| D9 | 节点排序 | **MVP 支持同级拖拽排序** | 调整顺序高频 |
| D10 | 大纲视图 | **MVP 只读侧栏**；P1 可编辑 | 与 Enter 幕布语义匹配 |
| D11 | 节点备注 | **MVP 加 note 字段 + popover** | 标题外的补充说明刚需 |
| D12 | task 联动 | **MVP 不做功能**，文档写明演进（MD 大纲→task 导入） | 形成产品闭环方向 |
| D13 | 移动端/无障碍 | **MVP 桌面优先**，声明降级 | 触控/读屏后置 |

## 十四、风险与注意事项

1. **🔴 OKLCH 主题**：项目用 OKLCH，禁用 `hsl(var())`；阶段 2 先 spike 验证深浅色 + 导出。
2. **🔴 shared 零依赖**：nodes/edges 用结构同构 interface，不引 @xyflow/react。
3. **🔴 keep-alive**：画布懒挂载 + 键盘绑容器 + 导出前校验挂载态。
4. **🔴 原子写**：所有 JSON 写操作走"临时文件+rename"。
5. **乐观锁**：PATCH 必带 version，409 提示刷新。
6. **后端 import 带 `.js`**（module:Node16）；改 shared 后重 build（`dev:shared`）。
7. **`createHttpServer`/`startHttpServer` 签名同步**两处加 mindmapService。
8. **动效别动 transform.translate**；节点尺寸靠 RF ResizeObserver。
9. **html-to-image 锁 1.11.11**；深色模式导出前强制背景色。
