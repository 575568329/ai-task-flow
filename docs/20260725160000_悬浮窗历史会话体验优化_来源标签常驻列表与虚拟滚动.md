# 悬浮窗历史会话体验优化：来源标签 + 常驻列表 + 虚拟滚动

> 日期：2026-07-25 ｜ 涉及模块：`frontend` 悬浮窗（projectChat）+ 共用 `MessageStream`
> 状态：设计待评审

---

## 一、背景与目标

悬浮窗（`FloatingChatWindow` → `ConversationPanel`）上线后暴露四个体验问题：

1. 历史会话列表项**没有标注 Win/WSL 来源**，用户不知道某个会话存在哪一侧的 Claude home。
2. 一个项目下虽可建多个对话（点「+」旧对话进历史、不丢），但悬浮窗同时只显示「当前一个」，多对话切换藏在顶栏历史 Popover 里，**体感像只能有一个对话**。
3. 历史会话消息多（几百条 + 大量 tool_use + Markdown）时，**悬浮窗明显卡顿**。
4. 在悬浮窗打开过的历史对话，到 Claude 终端 `/resume` 搜不到。

## 二、问题诊断（根因已定位）

| # | 问题 | 根因 | 是否改本项目代码 |
|---|------|------|------------------|
| ① | 历史项无 Win/WSL 标签 | 后端 `ClaudeSessionScanner.inferSessionSource` 已下发 `source`，`ConversationPanel` 漏渲染（对比 `TaskConversation.tsx:170` 已渲染） | 是（补渲染） |
| ② | 多对话不直观 | `startNew()` 已保留旧对话进历史，但 UI 无常驻列表，切换藏在 Popover | 是（加常驻列表） |
| ③ | 历史多→卡 | `MessageStream` 一次性 `turns.map` 全量渲染，无虚拟化/分页/懒渲染 | 是（虚拟列表） |
| ④ | `/resume` 搜不到历史 | **Claude Code 升级回归 bug**（#26123/#24536/#25729：新版 `/resume` 只列最近 5-10 个，不扫全部磁盘 jsonl）。本地 jsonl 完整无损，与本项目无关 | 否（claude 自身问题） |

**问题④的应对**：不改代码。workaround 是用 `claude --resume <sessionId>` 命令行参数（绕过 TUI `/resume` 列表），悬浮窗顶栏会话 ID 旁的复制按钮已提供该命令。问题①的来源标签正好补上「该去哪侧终端 resume」的指引。

## 三、设计方案

### 3.1 来源标签（Win/WSL）— 小改

- 数据已就绪：`ProjectSessionSummary.source` 由后端 `inferSessionSource(cwd)` 推断下发。
- **左侧对话列表项**（见 3.2）右侧加来源色标：`Win` / `WSL`，用 badge 变体区分颜色（遵循设计 token，不硬编码颜色）。
- 顶栏 side 切换保持现状（它代表「发消息用哪侧」，是操作而非只读标签）；历史会话的来源由左侧列表项展示。
- 对齐 `TaskConversation` 已有实现，保持两个入口观感一致。

### 3.2 常驻左侧对话列表 — 中改

用已有 `react-resizable-panels`（封装见 `components/ui/resizable.tsx`，v4 `Group/Panel/Separator` API）把悬浮窗**内容区**改为左右分栏：

```
FloatingChatWindow 内容区
└─ ResizablePanelGroup(horizontal)
   ├─ Panel(左侧, defaultSize=22, min=15, collapsible)   ← 新增 SessionList
   │    · 顶部「+ 新建对话」
   │    · 当前项目 sessions（按 lastActiveAt 倒序）
   │    · 每项：标题 / 来源色标 / 时间 / 条数 / 关联任务
   │    · 当前会话高亮；点击 → openSession(repoPath, id, source)
   ├─ ResizableHandle
   └─ Panel(右侧, defaultSize=78)                         ← 现有 ConversationPanel
```

- **per-project**：切项目 tab（顶栏 `selectProject`），左侧列表换成该项目的 `ProjectChatGroup.sessions`（数据源已是 `projects`）。
- **可收起**：Panel `collapsible` + `collapsedSize=0`，加 toggle 按钮；收起状态与宽度记忆到 localStorage（沿用 `FloatingChatWindow` bounds 同模式，不污染 store）。
- **顶栏去历史按钮**：左侧列表已覆盖历史切换，`ConversationPanel` 顶栏去掉历史 Popover + `historyOpen`/`repoSessions` 相关 state；顶栏保留：标题/关联任务/sessionId 复制/侧切换。「新建」也移入左侧列表顶部，顶栏不再放。

### 3.3 虚拟列表 — 中改

引入 `@tanstack/react-virtual`（headless、支持动态高度，适配不定高消息），改造**共用组件** `MessageStream`，taskChat 与 projectChat 同时受益：

- `useVirtualizer` + `estimateSize` + `measureElement` 动态测高，只渲染可视区 + 缓冲区。
- 滚动容器 `ref` 喂给 virtualizer 的 `count` / `getTotalSize` / `items`。
- **保留全部现有交互**：自动滚底（`scrollToIndex(last)` + `nearBottom` 判断）、流式「思考中」占位、过程折叠（`ProcessFold`）、终态 footer、复制、错误提示、空态。
- **流式增量优化**：对单个 turn 渲染加 `React.memo`（按 `turn.id` + 「是否当前流式末尾」），避免流式时全量 turns 重渲染。
- **Markdown 成本**：虚拟化后可视区仅十几条，Markdown 渲染成本从数百条降到十几条，足够；无需额外 Markdown 懒渲染。

## 五、关键决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 虚拟列表范围 | 改共用 `MessageStream`，taskChat 一起受益 | 共用组件一次改两处一致，避免任务对话以后内容多再改一遍 |
| 顶栏历史按钮 | 去掉 | 左侧列表已覆盖，避免两个入口指向同一份数据 |
| 左侧列表宽度/收起 | 可拖拽调宽 + 一键收起，localStorage 记忆 | 悬浮窗空间有限，收起后回到 chat-first 纯对话形态 |
| 虚拟列表库 | `@tanstack/react-virtual` | headless、动态高度支持好，适配不定高消息；react-window 对不定高支持差 |
| 问题④ | 不改代码 | Claude Code 自身升级回归 bug，workaround 用 `claude --resume <id>` 命令行 |

## 六、测试策略

- **单元**（Vitest + Testing Library）：
  - `MessageStream`：大量 turns（如 500 条）下仅渲染可视区条数（断言 DOM 节点数远小于 500）；发送后滚到底；流式末尾占位；空态。
  - `SessionList`：渲染来源色标（Win/WSL 各一）；当前 sessionId 高亮；点击触发 `onSelect(id, source)`；「新建」触发 `onNew`。
- **回归**：`TaskConversation` 接入虚拟化后，历史会话加载与发送行为不变。
- **手测**：悬浮窗打开含数百条消息的历史会话，首屏与滚动流畅度对比；左栏收起/展开/调宽/记忆；切项目列表正确切换。

## 七、范围外（YAGNI）

- 不做 Markdown 懒渲染 / 分页加载（虚拟列表已足够解决卡顿，不过度设计）。
- 不改 taskChat 加左侧列表（任务对话场景是「一任务一上下文」，历史是同仓库下会话；保留其现有 Popover）。
- 不动后端 `source` 推断逻辑与 `ClaudeSessionScanner`。
- 不为问题④做 claude 侧修复（属 claude 自身 bug）。
