# uTools 802px 紧凑模式适配设计

> 日期:2026-08-20 | 分支:`feat/utools-adapter` | 状态:已评审待实施
>
> 背景:uTools 7.8 主窗口宽 802px 固定,应用按 ≥1024 宽设计,现状 40+ 元素被裁、顶栏溢出约 354px。
> 目标:802px 下所有视图可用且好用;独立窗口拖窄到 <1024 时同样自动降级;宽屏体验零变化。

---

## 一、适配总原则(技术选型)

| 决策 | 结论 | 依据 |
|---|---|---|
| 断点阈值 | **1024px**(紧凑 <1024 / 宽敞 ≥1024) | 应用最低设计宽度;uTools 主窗 802 稳定落入紧凑 |
| main 内组件 | **容器查询**:`main` 挂 `@container`,变体 `@max-[1023px]:xxx` 覆盖式降级 | 视口断点测"窗户",容器查询测"房间":独立窗口 1100 + 侧栏展开 224 时 main 实际仅 876,视口断点会误判宽敞。Tailwind v4 原生支持 |
| portal 弹层组件 | **视口断点** `max-lg:xxx`(Radix Dialog/Sheet 渲染在 body,不在 main 容器内) | portal 元素脱离 @container 上下文 |
| 侧边栏(aside) | 视口 JS:`innerWidth < 1024` 时初始折叠 | aside 是 main 兄弟节点,同样不在容器内;初始判断 + localStorage 记忆优先 |
| 降级顺序 | 文字→图标(保留 title)→ 收窄宽度 → 收纳/隐藏,逐级递进 | 飞书响应式规范;保留可发现性 |
| 交互形态 | icon rail 为**固定栏+title 提示**,点击展开,不做 hover 展开 | Material 3 / VS Code 惯例;hover 展开有误触发与布局跳动问题 |

不引入新依赖,全部为 Tailwind v4 现有能力 + 一个 ~15 行的 `useNarrowViewport` hook。

**Chromium 108 兼容**:容器查询 Chrome 105+ 起支持,uTools 内核 108 满足;构建链已有 lightningcss chrome108 降级步骤,`@container` 规则会原样保留(测试断言覆盖)。

---

## 二、全局骨架

### 2.1 App.tsx

- `<main>` 增加 `@container` 类 → 容器查询上下文建立。
- 其余不动(keep-alive 视图结构、SSE、动画全部保留)。

### 2.2 SidebarNav(侧边导航)

现状:`w-56`(展开 224px)/`w-14`(折叠 56px),localStorage 记忆,默认展开。

| 元素 | 宽敞态(现状) | 紧凑态 |
|---|---|---|
| 品牌区 | logo + "AI Task Flow" + 折叠按钮 | 图标栏,顶部仅折叠按钮(ChevronRight) |
| 7 个导航项 | 图标+文字(看板/资料调研/任务文档/知识库/生词本/思维导图/用量) | 仅图标,`title` 提示已有 |
| 主题切换 | 图标+文字 | 仅图标 |
| 设置(含存储红点) | 图标+文字 | 仅图标,红点保留 |

改动:`useState` 初始值改为 `localStorage 有记忆 ? 记忆值 : (window.innerWidth < 1024)`。用户手动展开/折叠仍写记忆,不被运行时强改(避免使用中被收起)。

### 2.3 useNarrowViewport hook(新增)

`src/hooks/useNarrowViewport.ts`:`matchMedia('(max-width: 1023px)')` 监听,返回布尔。供 ResizablePanel 的 props 按断点取值(JS 层面,CSS 做不了)。

## 三、看板视图(board)——主战场

### 3.1 BoardToolbar 逐控件设计

现状合计约 932px,紧凑可用 578px,溢出 ~354px。

| # | 控件 | 宽敞态 | 紧凑态(`@max-[1023px]:`) | 省出 |
|---|---|---|---|---|
| 1 | SSE 状态(绿点+“已连接/断开”) | 点+文字 | 仅点(文字 `hidden @min-[1024px]:inline`,title 已有) | ~44px |
| 2 | 项目筛选 Select | `w-36`(144) | `w-28`(112) | 32px |
| 3 | 来源筛选 Select | `w-36`(144) | `w-28`(112) | 32px |
| 4 | 搜索 Input | `w-64`(256),placeholder“搜索标题或描述…” | `w-36`(144),placeholder 换短“搜索…” | 112px |
| 5 | 展开分组按钮 | 图标+文字 | 仅图标(title 已有) | ~58px |
| 6 | 收起分组按钮 | 图标+文字 | 仅图标 | ~58px |
| 7 | 新建任务按钮(ml-auto) | 图标+文字+快捷键 title | 仅图标(title 含快捷键) | ~68px |
| — | 容器 gap | gap-2 | `gap-1` | ~12px |

紧凑合计 ≈ 536px < 578px ✅(含侧栏展开最坏情况)。

### 3.2 Board 看板主体

已实现 Trello 模式:容器 `overflow-x-auto` + 列 `min-w-[260px] flex-1`,每列独立纵向滚动,**零改动**。

风险验证项(测试章节覆盖):dnd-kit 在横滚容器的自动滚动(GitHub #825/#1108);若实测抖动,加 `autoScroll={{ layoutShiftCompensation: false }}`。

### 3.3 TaskDrawer 任务抽屉(portal 弹层 → 视口断点)

现状:`SheetContent w-[80vw] sm:max-w-none`,内部三栏:元信息 `w-[240px]` 固定 | 步骤编辑 flex-1 | Markdown 预览 flex-1。
802 视口下 80vw=642px:三栏 240+190+190,步骤/预览不可用。

| 元素 | 宽敞态 | 紧凑态(`max-lg:`) |
|---|---|---|
| Sheet 宽度 | `w-[80vw]` | `w-[95vw]`(≈762px) |
| 元信息栏 | `w-[240px]` | `w-[170px]`,字段标签紧凑 |
| 三栏结构 | 保持 | 保持(170+280+280 ≈ 730 放得下) |

零结构改动,纯 className;预览栏保留(实时 Markdown 是核心功能,不裁剪)。

### 3.4 看板相关弹窗

- `OpenClaudeDialog`、卡片右键菜单、`confirm`/`alert-dialog`:居中小弹层,max-w 均小于 802,验证不溢出即可,预计零改动。
- `ImagePreviewOverlay`:全屏 fixed,自适应,零改动。

## 四、其他视图

| 消息气泡 | `max-w-[80%]` | 不变(百分比自适应) |
| 输入区 | 现状 | 验证不溢出,预计零改动 |

### 4.2 TaskDocsView(任务文档,ResizablePanelGroup)

| 元素 | 宽敞态 | 紧凑态 |
|---|---|---|
| 文件树 Panel | `defaultSize 28% min 18%` | `defaultSize 22% min 14%`(JS 变量) |
| 内容区 | 72% | 自动 |

### 4.3 KnowledgeView(知识库)

目录树 + 查看器分栏,实施时按 docs 同模式收紧树宽;header 徽章文字紧凑态隐藏。粒度以实施时代码为准,遵循同表登记。

### 4.4 VocabView(生词本)

已有响应式(翻译区 `md:w-96` 左栏/窄屏顶部堆叠),但 **md=768 断点对 802 误判**(802>768 走左栏模式,主内容仅剩 ~194px)。

改动:`md:w-96` → `@min-[1024px]:w-96`(容器查询,VocabView 在 main 内),紧凑态自动堆叠为上下布局。其余控件(`w-[120px]` Select、`w-64` Popover)802 下已可容纳,验证即可。

### 4.5 MindmapView / UsageView

- Mindmap:顶部输入 `max-w-xs` 已限制,画布 flex 自适应,预计零改动(验证工具条按钮)。
- Usage:卡片流式布局自适应,预计零改动。

### 4.6 悬浮层(FloatingDock / FloatingChatWindow)

`position: fixed` 独立悬浮,不受主布局挤压;FloatingChatWindow 内 tab 条已 `overflow-x-auto`,会话 Panel 已 collapsible。验证窗口默认宽 ≤ 视口即可,零改动。

### 4.7 SettingsDialog

居中 Dialog + tabs(设置/存储/LLM/Claude Profile 等),`max-w-*` 小于 802,验证项。

## 五、不适配清单及理由

| 组件 | 理由 |

| DragOverlay | 已 portal 到 body,最高层 |

## 六、测试方案

### 6.1 测试链路(自动化,每轮回归)

```
npm run build                     # 产物 → backend/public
node tools/utools-spike/downgrade-css.cjs <产物css> lc108.css   # 108 降级
grep -c '@container' lc108.css    # 断言:容器查询规则保留(>0)
node tools/utools-spike/serve-108.cjs &                          # 3108 托管
```

浏览器测试(ZCode 内置浏览器,browser-use 驱动):加载 `http://127.0.0.1:3108/`,分别设视口 **802×602**(uTools 主窗)与 **1920×1160**(独立窗,回归档),执行下表断言 + 交互冒烟 + 截图留档。

### 6.2 断言清单(802×602)

| # | 断言 | 方法 |
|---|---|---|
| A1 | 侧边栏初始折叠,宽度 56px | evaluate:`aside.getBoundingClientRect().width === 56` |
| A2 | 侧边栏点击可展开,localStorage 记忆生效 | 点击折叠按钮 → 复测宽度 224 |
| A3 | 顶栏无横向溢出 | evaluate:toolbar 内所有元素 `right ≤ clientWidth` |
| A4 | 搜索/筛选/新建任务均可见可点 | domSnapshot + 点击冒烟 |
| A5 | 看板三列:容器可横滚(`scrollWidth > clientWidth`),列宽 ≥260 | evaluate |
| A6 | 拖拽卡片跨列:横滚边缘自动滚动或手动滚动后可 drop | cua.drag 冒烟 |
| A7 | TaskDrawer 打开:Sheet ≤95vw,三栏均宽 ≥170,无溢出 | evaluate |
| A8 | chat:会话列表默认收起,主区 ≥500px | domSnapshot + evaluate |
| A9 | docs:树 + 内容无溢出,树可拖宽 | evaluate |
| A10 | vocab:上下堆叠布局(翻译区全宽) | evaluate:翻译区 width ≈ 容器宽 |
| A11 | 1920×1160 全量回归:侧栏展开、顶栏全文字、三栏 Drawer | 同法复测,断言反向 |
| A12 | `@container` 在降级 CSS 中保留 | grep 构建产物 |

### 6.3 人工验收(uTools 内)

1. 重拖 plugin.json(preload 已在之前版本就绪);`alt+space` → atf
2. 主窗 802:看板完整、顶栏不挤、抽屉可用、逐视图切换检查
3. 独立窗口:拖窄至 <1024 观察自动降级;拖宽恢复;重开 uTools 记忆保持

### 6.4 回归红线

宽屏(≥1024)下任何视觉变化均视为回归——所有降级类必须以 `@max-[1023px]:`/`max-lg:` 覆盖式书写,不改动默认分支。
