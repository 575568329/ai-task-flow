# 思维导图设计审阅记录

> 审阅日期：2026-08-12
> 审阅对象：`20260812154305_思维导图功能设计.md`（v2）
> 审阅视角：架构师 / 前端资深开发 / 后端资深开发 / 产品 UX（四路并行）

本文档记录四方审阅意见及**采纳结论**，作为设计 v3 的修订依据。

## 一、阻断项（必须先解决，已全部纳入 v3）

| # | 问题 | 指出方 | v3 修订方案 |
|---|------|--------|-------------|
| B1 | shared 包不能依赖 `@xyflow/react`（会把前端画布库拖进后端编译链） | 架构师+前端+后端 | shared 手写**结构同构**的 `MindmapFlowNode/Edge` interface，零 xyflow 依赖；靠 TS 结构类型让前端 `Node[]` 兼容 |
| B2 | 视觉章节全部用 `hsl(var(--card))`，但本项目是 **OKLCH**，整条 CSS 被丢弃 | 前端 | 去掉 `hsl()` 包裹直接 `var(--card)`；8 色色板重算成 `oklch(L C H)` |
| B3 | keep-alive 架构下 React Flow 常驻 DOM（键盘泄漏/内存累积/导出脏数据） | 架构师+前端 | MindmapView 内部按"active + 有无打开文档"条件渲染画布；nodes/edges 暂存 store，切回重建 |
| B4 | 导出 PNG 写进 MVP 目标却在 P2；自动保存 D5 建议做却在 P2 | 产品 | 导出 PNG/SVG、自动保存(debounce 2s) 升入 MVP；统一优先级消除矛盾 |
| B5 | 空状态/首次引导完全缺失 | 产品 | MVP 补：空列表页 + 示例文档 + 首次快捷键气泡 + `?` 快捷键面板 |

## 二、重要项（已纳入 v3）

| # | 问题 | 指出方 | v3 修订方案 |
|---|------|--------|-------------|
| I1 | store 切分的"dirty 桥"未设计（怎么从内部 store 拿数据保存） | 前端 | 明确**受控模式**：nodes/edges 本地 `useState` + `onNodesChange`；debounce markDirty 桥到项目 store；保存时序列化本地 state |
| I2 | 聚合根贫血，后端零不变量守护 | 架构师+后端 | 聚合根守**存储不变量**：node.id 非空唯一、edge 引用完整、标题非空、上限校验；不校验布局（前端职责） |
| I3 | 单文件全量重写：大文档性能 + 写崩溃丢全部 | 架构师 | 写操作改"临时文件 + `fs.rename` 原子替换"（vocab 的 saveAll 一并受益）；MVP 仍单文件，注释演进到每文档一文件 |
| I4 | 无乐观锁，多 tab 互相静默覆盖 | 架构师+后端 | DTO 加 `version`；PATCH 带 `If-Match`，冲突返 409；前端提示刷新 |
| I5 | nodeCount 列表性能（每次 list 全量解析所有图） | 后端 | 存储**冗余 nodeCount**，list 直接读 meta，不解析 nodes |
| I6 | FileLogger / 类型化错误 / 测试策略集体缺失 | 架构师+后端 | 照 vocab 补：`FileLogger('mindmap')`、`MindmapNotFoundError/ValidationError/ConflictError`、聚合根+Service 单测 |
| I7 | PUT 与 vocab 的 PATCH 不一致；DTO 全可选更像 PATCH | 架构师+后端 | PUT → **PATCH** |
| I8 | 缺校验上限 / 审计字段 / 软硬删策略 | 后端 | 定上限常量（标题/节点数/文档数/字节）；补审计字段；MVP 硬删 + 前端"撤销删除"toast(5s) |
| I9 | dim-others 聚焦效果用 setEdges 会破 memo | 前端 | 改走 **CSS 属性选择器**（`.react-flow[data-hover-branch]`），零 state 变更 |
| I10 | 节点尺寸"写回"机制不清 | 前端 | 依赖 RF 内置 ResizeObserver，禁止手写 `node.width/height`；统一尺寸用 `updateNodeInternals` |
| I11 | 删除不可逆（误删清零） | 产品 | MVP：硬删 + 撤销 toast；P1：软删回收站 |
| I12 | 节点备注、兄弟节点排序缺失 | 产品 | MVP 补 `note?` 字段（轻量 popover）；MVP 支持同级拖拽排序（改 tree 顺序） |
| I13 | 与 task 看板零联动（产品定位错位） | 产品 | MVP 不做功能，文档写明演进方向：导出 Markdown 大纲 → task 从 MD 导入 |

## 三、建议项（登记，择机采纳）

- 查找替换 / 图标标记 / 历史版本：P1/P2。
- 移动端/无障碍：MVP 桌面优先，声明降级。

## 五、结论

v2 前端视觉/交互/性能章节方向正确但有两处地基错误（OKLCH、shared 耦合），后端章节明显欠账，产品完整度有结构性缺口。四方意见收敛度高。**v3 已将上述阻断项与重要项全部落实**，可作为实施依据。
