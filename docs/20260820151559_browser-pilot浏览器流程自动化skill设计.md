# browser-pilot — 通用浏览器流程自动化 Skill 设计

> 状态:设计定稿(已经 架构师/资深开发/产品经理 三角色 agent + Playwright 官方文档 审阅修订)
> 日期:2026-08-20
> 作用域:全局 skill(`~/.claude/skills/browser-pilot/`),不绑定 ai-task-flow 项目

---

## 1. 背景与目标

用户需要一个让 Claude Code 直接操作浏览器的 skill,两类核心诉求:

1. **日常事务自动化**:向公司内部 web 系统(账号密码登录)提交日报。内容从已有 skill `daily-cc-stats` 生成的报告提炼。
2. **开发测试**:对本地前端(如 ai-task-flow 看板 `localhost:5678`)做随时冒烟验证,以及可重复的固化 E2E 流程。

经澄清,**定位为通用浏览器流程自动化 skill**:支持录制多个网页操作流程(日报/周报/报销/打卡…),录一次、之后按名回放。不做日报专用(用户明确决策通用化)。

## 2. 需求澄清结论

| 维度 | 结论 |
|------|------|
| 日报目标 | 公司内部 web 系统,网页表单提交 |
| 登录方式 | 账号密码可自动登录(但设计以持久 profile 优先,密码仅兜底) |
| 日报内容来源 | 从 `daily-cc-stats` 生成的 `~/Desktop/日报/CC使用报告_YYYY-MM-DD.md` 提炼简版 |
| 开发测试形态 | 随时冒烟 + 固化 E2E(两者都要,先冒烟) |
| 通用性 | 流程库机制,任意网页流程可录制可回放 |
| 作用域 | 全局(与用户现有 6 个 skill 同目录) |

## 3. 方案选型

| 方案 | 结论 |
|------|------|
| **A. Playwright MCP + Markdown 流程库** | ✅ 采用 |
| B. 录制后生成真 Playwright 脚本回放 | ❌ 写死选择器易碎;日报内容天然需 LLM 在环,两套机制维护成本高 |
| C. Chrome DevTools MCP 为底座 | ❌ 强在性能/网络调试,弱在日常操作;可作为以后调性能时按需补装 |

选 A 的核心理由:流程文件记**语义步骤**(靠无障碍树现场定位元素,不写死 CSS 选择器),对内部系统改版鲁棒;LLM 解释执行恰好匹配"生成内容+填表"混合场景。

## 4. 架构

```
~/.claude/
├── skills/browser-pilot/SKILL.md     ← 指令层(skill 本体,可独立升级)
└── browser-pilot/                    ← 数据层(与 skill 分离,升级不丢数据)
    ├── flows/                        ← 流程库(本地 git 仓库,历史可回滚)
    │   ├── 日报.md
    │   └── 冒烟-任务看板.md
    ├── secrets.json                  ← 账密(仅本机;可选 DPAPI 加密,见 §8)
    └── profile/                      ← 统一浏览器 profile(若核实支持统一目录,见 §5)
```

执行底座:**Playwright MCP**(唯一新增依赖)。skill 是指挥层,决定打开哪、点什么、填什么;MCP 负责真正的浏览器操作。

## 5. 安装与底座

```bash
claude mcp add playwright --scope user -- cmd /c npx -y @playwright/mcp@<锁定版本>
npx playwright install chromium
```

要点(均来自审阅修订):

- **`--scope user`**:全局所有项目可用;`cmd /c` 为 Windows 下 npx 的必要包装(本机 zai-mcp-server 有成功先例)。
- **锁定版本**:不用 `@latest`——版本漂移可能改工具 schema 使流程全废;内网/离线时 npx 解析 latest 直接起不来。升级走显式验证。
- **chromium 二进制预装**:官方文档未明说,实施时若启动报缺浏览器,执行 `npx playwright install chromium`。
- **⚠️ 待实施首项核实——统一 profile**:官方默认 profile 按「浏览器 channel + 项目目录哈希」分目录,**换项目目录登录态即丢**。实施第一步核实 MCP 是否支持 `--user-data-dir` 类参数将 profile 固定到 `~/.claude/browser-pilot/profile/`;若不支持,退路是 `--storage-state` 指向固定存档文件。
- 默认 chromium(不用 `--extension` 连日常 Chrome:日报等操作会打断日常浏览;持久 profile 已解决登录态)。

## 6. 流程文件格式(核心资产)

Markdown + YAML frontmatter,人可读可手改,Claude 解释执行:

```markdown
---
name: 日报
entry: https://oa.example.com/daily/new
confirm: always            # always=每次提交前确认 | auto-after-trust=连续N次无修改后展示即提交
variables:
  content: { source: daily-cc-stats, desc: 日报正文 }
---
1. 打开 {{entry}};若跳登录页:按「登录」子流程处理
2. 「工作内容」编辑框填入 {{content}}(富文本:fill 失败→evaluate 注入→剪贴板粘贴 三级降级)
3. 点「提交」
4. ✅校验:页面出现"提交成功"提示
```

约定:

- **语义步骤,不写 CSS 选择器**;录制时可把命中元素的角色/名称文本作为 fallback 锚点附注。
- 动态内容用 `{{变量}}`,凭据用 `{{secrets.<系统>.<字段>}}` 引用——**凭据值永不写入流程文件**。
- 单流程 **≤10 步**;公共部分(如登录)抽子流程引用,避免多系统重复内嵌、密码轮换改 N 处。
- **执行前校验** frontmatter 完整性与占位符配对,校验失败显式报错不执行(防手改坏)。
- **`flows/` 初始化为本地 git 仓库**:流程每次自动更新前留 diff,展示变更待用户确认后提交——一次坏更新可回滚。
- frontmatter 预留 `confirm`/风险分级字段,为将来"定时无人值守"留门(无人值守模式仅白名单流程、默认止步草稿;本期不实现定时)。

## 7. Skill 三条工作路径

| 用户说的话 | 路径 | 行为 |
|-----------|------|------|
| "写日报" / "跑看板冒烟" | **回放** | 查 `flows/` → 收集变量(取数/询问)→ 按步骤执行 → 校验 → 截图汇报 |
| "帮我录个XX流程" / 回放发现流程不存在 | **沉淀** | Claude 用自由操作完成该任务(全程截图快照),完成后把实际步骤复盘写成流程文件(动态内容变量化),**立即试跑一遍验证**后入库 |
| "打开 localhost:5678 建个任务看看" | **自由操作** | 不建流程,直接执行+截图汇报(冒烟) |

沉淀路径说明(审阅修订):原设计的"用户口述逐步带路"降级为"Claude 自由操作完成后自动沉淀"——首录成本趋近于零,且避免口述歧义(同名按钮/iframe/多标签页)。Claude 操作过程中用户可随时插话纠偏。

## 8. 凭据与安全

1. **登录态优先靠持久 profile**:首次由用户人工在浏览器内登录一次,cookie 长期存活,日常不碰账密。
2. **密码仅兜底**(profile 失效时重登),存 `~/.claude/browser-pilot/secrets.json`。
3. **泄漏面明示**:密码值替换后会作为工具参数进入本地会话记录(jsonl)与权限弹窗——属已知残留风险,SKILL.md 写明,并立红线:
   - 密码不进日志,任何回显/截图必须脱敏;
   - **替换后的真值永不落盘**(不回写流程文件/汇报文本);
   - 流程文件、截图、汇报外发前扫描 `{{secrets.*}}` 与真值。
4. MVP 明文存储 + 上述红线;**DPAPI 加密(PowerShell ProtectedData,CurrentUser 域)列为可选加固**,默认不启用(KISS)。
5. **不可逆动作(提交/发送)**:按流程 `confirm` 字段执行——`always` 每次先展示将提交内容,用户确认再点;`auto-after-trust` 连续 N 次(默认 3)无修改后降为展示即提交,异常时拦下。

## 9. 日报串联数据流

```
"写日报"
→ flows/日报.md 存在?
→ 变量 content 取数:~/Desktop/日报/CC使用报告_今天.md
   已有→直接读;没有→先触发 daily-cc-stats 生成
   (容错:同日多次生成会有 _v2 后缀,取最新;daily-cc-stats 侧不做任何修改)
→ 提炼为公司日报简版(今日完成/明日计划/问题)
→ 按 confirm 策略展示确认
→ 回放流程填入 → 提交 → 截图汇报
```

理想动线:一句话 → 1 次确认 → 截图回报,**压进 1 分钟**;超 3 分钟用户会弃用。

## 10. 错误处理与健壮性

| 故障 | 处理 |
|------|------|
| 元素找不到 | 重新 snapshot 语义重找一次(fallback 锚点辅助)→ 仍失败:截图问用户"是否改版,指一下";修正后更新流程文件(diff 确认入 git) |
| 登录态失效 | 检测登录页特征 → 先试 secrets 重登 → 失败问人 |
| 富文本填入失败 | 三级降级:fill → evaluate 注入 → 剪贴板粘贴 |
| 校验点不过 / 验证码/风控 | 截图+原始错误如实汇报,**交还人工补交**,不静默不硬重试 |
| MCP 超时/浏览器崩溃 | 页面状态未知时**先重新快照重建状态再动作**(防重复提交);流程支持从第 N 步续跑 |
| 并发 | **单会话执行约定**:同 profile 第二实例会撞锁,捕获后显式上报,不静默 |
| 流程末尾 | 强制 `browser_close`;附 chromium 残留进程清理指引(taskkill) |
| localhost 不通 | HTTP 实测探活(非进程/文件信号),失败直接引导/执行 dev-launcher 启动(衔接现有 skill,不重复造) |
| 流程文件手改坏 | 执行前校验(§6),失败显式报错 |

**预期管理**(写进 SKILL.md):定位是"大概率每天省 5 分钟",不是 100% 可靠自动化;公司系统可能检测自动化特征,保持低频使用。

## 12. 验收清单

1. MCP 装好(锁版本)重启,浏览器工具可见;chromium 可启动(缺则 install)
2. **统一 profile 核实**:两个不同项目目录下登录态一致(或 storage-state 方案生效)
3. 冒烟:打开任一公网页截图
4. 冒烟:localhost:5678 建任务截图(衔接 dev-launcher)
5. 沉淀一个极简流程(如"打开 GitHub Trending 截图")→ 回放成功
6. **真实日报首录**(Claude 自由操作完成+沉淀流程,富文本实测)→ 次日"写日报"一键回放,动线 ≤1 分钟
