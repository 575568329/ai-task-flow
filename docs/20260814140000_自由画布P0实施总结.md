## 二、实施决策记录（偏离设计的部分）

### D1. 不新建 CanvasService/canvasRoutes（P0b-3 收窄）

设计文档 P0b 清单含"CanvasService CRUD + canvasRoutes HTTP CRUD"。实施时发现：P0b 已决定**留在单文件 `mindmaps.json` + 同一聚合根**，现有 `MindmapService`/`mindmapRoutes` 已提供完整 CRUD + DomainError 四件套 + 乐观锁——再建平行模块是纯重复。改为：扩展现有 curl 测试覆盖画布新字段。真正的画布新后端能力（语义摘要/MCP 工具/zip 导出）按计划属 P1b，届时落地 CanvasService。

### D2. 浮边算法自写而非照抄官方

官方 FloatingEdges 的 `getNodeIntersection` 用对方节点尺寸算中心有已知瑕疵（假设两节点同尺寸）。自写版本改为正确的射线-矩形求交（`t = min(tx, ty)`），语义更准且可测。单方向求交只依赖自身 measured（对方未测时退化为其左上角，与官方一致）。

### D3. RF 版本差异适配

项目 `@xyflow/react` 12.11.3 的 store **无 `connectionStartHandle`**（新版才有），拖拽连线起始节点改用 `s.connection.fromNode`（`connection.inProgress` 时）。

### D4. 拖拽撤销快照时序修正（顺手修的存量 bug）

原 `onNodeDragStop` 拍快照——拍的是**拖后**状态，该撤销步无效（撤销回到拖后=无变化）。修正为 `onNodeDragStart` 拍（变更前），符合 useUndoRedo 的"变更前快照"契约。

### D5. 模式判定用启发式而非 docMode 字段

`isTreeDocument`（存在无入边节点 + 所有节点入度≤1）区分树形/画布操作语义。**局限**：恰好构成树形的自由画布会走树形语义（Tab/Enter/删子树）。P1 若引入 `docMode` 字段可消除歧义。

### D6. Delete 语义双轨 + RF 内置删除禁用

`deleteKeyCode={null}` 禁用 RF 内置删除，统一由 `handleKeyDown` 分流：树形=删子树（原行为），画布=删选中节点+选中边（单事务单快照）。
