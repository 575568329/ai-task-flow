## 一、背景与目标

### 1.1 背景

项目当前**全站零右键菜单**（`grep onContextMenu` 无命中）。各模块操作入口分散在三种形态：工具栏按钮、抽屉底部按钮、hover 才出现的幽灵按钮。第三类（hover 幽灵按钮）触屏/小屏完全够不着；"要点开抽屉才能做"的操作路径过长；部分能力（聊天重新生成、思维导图改色）后端已就绪但前端无入口。

右键菜单是补齐这些缺口、统一操作体验的最自然承载位。

### 1.2 目标

设计一套**通用、可扩展、模块化**的右键菜单系统：

- **全项目可用**：不止思维导图，看板/聊天/知识库/生词本/文档/悬浮窗都能用
- **不同页面不同功能**：按上下文（右键的目标对象）动态切换菜单内容
- **扩展性好**：新模块接入零改动核心组件
- **模块化**：各模块独立维护自己的菜单项定义

**首批接入**：思维导图节点（解决当前"节点操作只能靠键盘"的痛点）。架构验证后，其他视图分批铺。

## 三、架构设计

### 3.1 三层架构

```
┌─────────────────────────────────────────────────────┐
│ ③ 模块层（各视图自定义）                              │
│   mindmap/nodeContextMenu.ts  buildMindmapNodeItems  │
│   board/taskContextMenu.ts    buildTaskCardItems     │
│   chat/messageContextMenu.ts  buildMessageItems      │
│   ...（每个模块一个工厂 + 自己的 MenuCtx 类型）       │
├─────────────────────────────────────────────────────┤
│ ② 抽象层（通用、类型安全、不耦合业务）                │
│   context-menu/types.ts        MenuItem<T,C> 联合    │
│   context-menu/ContextMenuHost.tsx  通用包装+渲染    │
├─────────────────────────────────────────────────────┤
│ ① 底层 UI（shadcn 原子组件）                         │
│   ui/context-menu.tsx         封装 radix（shadcn add）│
└─────────────────────────────────────────────────────┘
```

**职责边界**：
- ① 只封装 radix 原语，不含任何业务/数据逻辑
- ② 只负责"把 MenuItem 数据渲染成 radix 组件"，不认识任何具体业务
- ③ 各模块定义自己的菜单项 + 上下文类型，互相独立

### 3.2 数据流

```
用户右键目标元素
    ↓
ContextMenuHost 捕获，构造 MenuContext{ target, ctx }
    ↓
解析 items（数组直接用 / 函数则传入 MenuContext 调用）
    ↓
过滤 hidden、求值 disabled/动态 label
    ↓
递归渲染 → Radix ContextMenu.Item / Separator / Sub / Label
    ↓
用户点击 → onSelect(MenuContext) → 模块回调
```

## 四、核心类型设计

### 4.1 设计原则

- **双泛型 `<T, C>`**：`T` = 右键目标对象类型（节点/任务/消息），`C` = 模块上下文（回调集合）。让每个模块的菜单项完全类型安全。
- **数据驱动**：MenuItem 是普通数据结构（非组件），可动态生成、按状态显隐、易于跨模块复用。
- **可扩展**：union 类型，新增 menu item kind（如 checkbox/radio）只需加一个分支，不破坏现有。

### 4.2 类型定义（`components/context-menu/types.ts`）

```ts
import type { LucideIcon } from 'lucide-react';

/** 右键上下文：target=目标对象，ctx=模块回调集合 */
export interface MenuContext<T, C = unknown> {
  target: T;
  ctx: C;
}

/** 动态谓词：可为静态值，或按上下文求值的函数 */
type Predicate<C> = boolean | ((c: C) => boolean);
type Dynamic<V, C> = V | ((c: C) => V);

/** 普通动作项 */
export interface MenuAction<T, C = unknown> {
  type: 'action';
  key: string;
  label: Dynamic<string, MenuContext<T, C>>;
  icon?: LucideIcon;
  shortcut?: string;                 // 显示用，如 'Tab' / 'Ctrl+S'
  disabled?: Predicate<MenuContext<T, C>>;
  hidden?: Predicate<MenuContext<T, C>>;
  danger?: boolean;                  // true → 红色（删除等）
  onSelect: (c: MenuContext<T, C>) => void;
}

/** 分隔符 */
export interface MenuSeparator {
  type: 'separator';
  key: string;
}

/** 分组标题（不可点） */
export interface MenuLabel {
  type: 'label';
  key: string;
  label: string;
}

/** 子菜单 */
export interface MenuSubmenu<T, C = unknown> {
  type: 'submenu';
  key: string;
  label: string;
  icon?: LucideIcon;
  disabled?: Predicate<MenuContext<T, C>>;
  hidden?: Predicate<MenuContext<T, C>>;
  items: Dynamic<MenuItem<T, C>[], MenuContext<T, C>>;
}

export type MenuItem<T, C = unknown> =
  | MenuAction<T, C>
  | MenuSeparator
  | MenuSubmenu<T, C>
  | MenuLabel;

/** 菜单项工厂函数签名（模块层实现） */
export type MenuItemBuilder<T, C> = (c: MenuContext<T, C>) => MenuItem<T, C>[];
```

> 后续扩展（不在本次）：`MenuCheckboxItem`、`MenuRadioGroup` —— 加进 union 即可，核心渲染 switch 多一个 case。

## 五、ContextMenuHost 通用组件

### 5.1 接口（`components/context-menu/ContextMenuHost.tsx`）

```tsx
interface ContextMenuHostProps<T, C> {
  /** 菜单项：静态数组 或 按上下文动态生成的工厂 */
  items: MenuItem<T, C>[] | MenuItemBuilder<T, C>;
  /** 右键目标对象（传给菜单项的 MenuContext.target） */
  target: T;
  /** 模块上下文（回调集合，传给 MenuContext.ctx） */
  ctx: C;
  /** 被包裹的目标元素（右键触发区） */
  children: React.ReactNode;
  /** Content 自定义类名（定位/宽度等） */
  contentClassName?: string;
}

export function ContextMenuHost<T, C>(props: ContextMenuHostProps<T, C>): React.JSX.Element;
```

### 5.2 渲染逻辑

1. `<ContextMenu.Root>` + `<ContextMenu.Trigger asChild>{children}</ContextMenu.Trigger>`
2. `<ContextMenu.Portal>` + `<ContextMenu.Content className="z-[1400] ...">`
3. 解析 `items`：若是函数，传入 `{target, ctx}` 调用得数组
4. 遍历，**过滤 `hidden`**（求值后为 true 的不渲染），连续 separator 去重
5. 按 `type` 渲染：
   - `action` → `<ContextMenu.Item>`，`disabled` 求值，`danger` 加 `text-destructive`，`icon` + `shortcut` 右对齐显示
   - `separator` → `<ContextMenu.Separator>`
   - `label` → `<ContextMenu.Label>`
   - `submenu` → `<ContextMenu.Sub>` + `<SubTrigger>` + `<SubContent>`（递归渲染子 items）
6. `onSelect` 调用时传入 `{target, ctx}`

### 5.3 代码骨架

```tsx
import { ContextMenu } from '@/components/ui/context-menu';
import { cn } from '@/lib/utils';
import type { MenuItem, MenuContext, MenuItemBuilder } from './types';

export function ContextMenuHost<T, C>({
  items, target, ctx, children, contentClassName,
}: {
  items: MenuItem<T, C>[] | MenuItemBuilder<T, C>;
  target: T; ctx: C; children: React.ReactNode; contentClassName?: string;
}) {
  const menuCtx: MenuContext<T, C> = { target, ctx };
  const resolved = typeof items === 'function' ? items(menuCtx) : items;

  return (
    <ContextMenu.Root>
      <ContextMenu.Trigger asChild>{children}</ContextMenu.Trigger>
      <ContextMenu.Portal>
        <ContextMenu.Content className={cn('z-[1400] w-52', contentClassName)}>
          {resolved.map((item) => renderMenuItem(item, menuCtx))}
        </ContextMenu.Content>
      </ContextMenu.Portal>
    </ContextMenu.Root>
  );
}

/** 递归渲染单个 item（处理 hidden/disabled/danger/shortcut/submenu） */
function renderMenuItem<T, C>(item: MenuItem<T, C>, c: MenuContext<T, C>) {
  if (isHidden(item, c)) return null;
  switch (item.type) {
    case 'separator': return <ContextMenu.Separator key={item.key} />;
    case 'label':    return <ContextMenu.Label key={item.key}>{item.label}</ContextMenu.Label>;
    case 'submenu':
      const subItems = typeof item.items === 'function' ? item.items(c) : item.items;
      return (
        <ContextMenu.Sub key={item.key}>
          <ContextMenu.SubTrigger disabled={val(item.disabled, c)}>
            {item.icon && <item.icon className="size-4" />} {item.label}
          </ContextMenu.SubTrigger>
          <ContextMenu.Portal>
            <ContextMenu.SubContent>
              {subItems.map((sub) => renderMenuItem(sub, c))}
            </ContextMenu.SubContent>
          </ContextMenu.Portal>
        </ContextMenu.Sub>
      );
    case 'action':
      const Icon = item.icon;
      return (
        <ContextMenu.Item
          key={item.key}
          disabled={val(item.disabled, c)}
          onClick={() => item.onSelect(c)}
          className={cn(item.danger && 'text-destructive focus:text-destructive')}
        >
          {Icon && <Icon className="size-4" />}
          <span>{val(item.label, c)}</span>
          {item.shortcut && <span className="ml-auto text-xs opacity-50">{item.shortcut}</span>}
        </ContextMenu.Item>
      );
  }
}

const val = <V,>(v: V | ((c: never) => V), c: never): V => (typeof v === 'function' ? (v as (c: never) => V)(c) : v);
const isHidden = <T, C>(item: MenuItem<T, C>, c: MenuContext<T, C>): boolean =>
  'hidden' in item && item.hidden ? val(item.hidden as never, c as never) : false;
```

> `val`/`isHidden` 的类型推导细节在实现时细化，骨架示意求值逻辑。

### 6.2 菜单工厂（`components/mindmap/nodeContextMenu.ts`）

```ts
import { Pencil, Plus, Trash2, Palette, ChevronDown, ChevronRight } from 'lucide-react';
import type { BranchKey } from '@ai-task-flow/shared';
import type { MindmapNodeData } from '@ai-task-flow/shared';
import type { MenuItem, MenuItemBuilder } from '@/components/context-menu/types';

/** 思维导图右键上下文（回调集合） */
export interface MindmapMenuCtx {
  edit: (id: string) => void;
  addChild: (id: string) => void;
  addSibling: (id: string) => void;
  deleteNode: (id: string) => void;
  toggleExpand: (id: string) => void;
  setBranch: (id: string, branch: BranchKey) => void;
  hasChildren: (id: string) => boolean;
}

/** 8 色定义（与 index.css 的 --branch-* 对应） */
const BRANCH_COLORS: { key: BranchKey; label: string }[] = [
  { key: 'blue', label: '蓝' }, { key: 'teal', label: '青' },
  { key: 'emerald', label: '绿' }, { key: 'amber', label: '琥珀' },
  { key: 'orange', label: '橙' }, { key: 'rose', label: '玫红' },
  { key: 'violet', label: '紫' }, { key: 'indigo', label: '靛' },
];

type Target = { id: string; data: MindmapNodeData };

export const buildMindmapNodeItems: MenuItemBuilder<Target, MindmapMenuCtx> = ({ target, ctx }) => {
  const { id, data } = target;
  const isRoot = (data.level ?? 1) === 0;
  const collapsed = data.expanded === false;
  return [
    { type: 'action', key: 'edit', label: '编辑文本', icon: Pencil, onSelect: () => ctx.edit(id) },
    { type: 'separator', key: 's1' },
    { type: 'action', key: 'child', label: '添加子节点', icon: Plus, shortcut: 'Tab', onSelect: () => ctx.addChild(id) },
    { type: 'action', key: 'sibling', label: '添加同级节点', icon: Plus, shortcut: 'Enter', disabled: isRoot, onSelect: () => ctx.addSibling(id) },
    { type: 'separator', key: 's2' },
    {
      type: 'submenu', key: 'color', label: '分支颜色', icon: Palette,
      items: BRANCH_COLORS.map((c) => ({
        type: 'action', key: c.key, label: c.label, onSelect: () => ctx.setBranch(id, c.key),
      })),
    },
    {
      type: 'action', key: 'toggle',
      label: collapsed ? '展开子节点' : '折叠子节点',
      icon: collapsed ? ChevronRight : ChevronDown,
      hidden: !ctx.hasChildren(id),
      onSelect: () => ctx.toggleExpand(id),
    },
    { type: 'separator', key: 's3' },
    { type: 'action', key: 'delete', label: '删除', icon: Trash2, danger: true, disabled: isRoot, onSelect: () => ctx.deleteNode(id) },
  ];
};
```

### 6.3 MindmapNode 接入（改造点）

```tsx
// MindmapNode.tsx
const { updateNodeData, addChildNode, addSiblingNode, deleteNode, toggleExpand, hasChildren } = useMindmapEditor();
const [editing, setEditing] = useState(false);

// 构造右键上下文（edit 复用本地 setEditing，其余复用 editor actions）
const menuCtx: MindmapMenuCtx = {
  edit: () => setEditing(true),
  addChild: addChildNode,
  addSibling: addSiblingNode,
  deleteNode,
  toggleExpand,
  setBranch: (id, branch) => updateNodeData(id, { branch }),
  hasChildren,
};

return (
  <ContextMenuHost items={buildMindmapNodeItems} target={{ id, data }} ctx={menuCtx}>
    <div className="mm-card ..." onDoubleClick={() => setEditing(true)}>
      {/* 原节点内容不变 */}
    </div>
  </ContextMenuHost>
);
```

> `ContextMenu.Trigger asChild` 把 onContextMenu 绑到内层 div，div 原有的 `onDoubleClick`/className/handle 等全部保留，不冲突。

## 九、设计取舍与不做项

### 9.1 取舍
| 决策 | 选择 | 理由 |
|------|------|------|
| 菜单定义风格 | **数据驱动工厂**（非 JSX 组合） | 类型安全、动态显隐、跨模块复用、易序列化 |
| 泛型 | **双泛型 `<T,C>`** | target 与 ctx 都类型安全，模块间不串类型 |
| 底层组件 | **shadcn context-menu**（radix） | 标准无障碍、焦点/键盘/碰撞翻转成熟，不手写 |
| Host 位置 | 抽象层（`context-menu/`），不进 ui/ | ui/ 只放纯原子，Host 含数据驱动逻辑属业务抽象 |
| z-index | portal 到 body，`z-[1400]` | 浮窗 1300、抽屉 Sheet 之下不被遮 |

### 9.2 本次不做
- 其他 6 视图的右键接入（架构验证后分批）
- 后端缺口补齐（知识库 rename/移动、删消息、生词单条加墨墨）—— 需单独排期
- checkbox/radio 类型菜单项（union 预留扩展点，按需加）
- tooltip（菜单项悬停提示）—— 需另装 `@radix-ui/react-tooltip`

## 十、风险与注意事项

1. **Radix 版本兼容**：`npx shadcn add` 装的 `@radix-ui/react-context-menu` 版本需与 React 19 兼容（radix 1.1.x 已支持，装时确认）。
2. **z-index 层级**：菜单必须 `z-[1400]`，否则被 TaskDrawer(Sheet)/FloatingChatWindow 遮挡。
3. **拖拽冲突**：TaskCard 用 dnd-kit draggable，contextmenu 事件不触发拖拽，但菜单项 onSelect 要 `stopPropagation`（Host 内部已处理）。
4. **虚拟列表**：聊天 MessageStream 用 `content-visibility:auto`，右键需确保 contextmenu 事件不被屏外跳过渲染影响（实测确认）。
5. **快捷键显示**：复用 `lib/shortcuts.ts` 的 `formatCombo`，菜单项 `shortcut` 字段填显示文本（如 'Tab'/'Ctrl+S'），不重复定义。
6. **删除类操作**：统一走 `useConfirm()` + toast，菜单项只触发、不在菜单内做确认 UI。
7. **shadcn 生成代码风格**：对齐新代（dialog/select/button），若生成的 context-menu.tsx 是旧代 forwardRef 风格，手动转新代（函数组件 + data-slot）。
