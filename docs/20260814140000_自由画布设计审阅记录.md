## 🔴 严重问题（开工前必须解决，共 12 项）

### S1. 跨进程写并发零防护 —— 最致命，agent 写 + 用户拖 = 静默丢数据

**提出者**：后端架构师 #1、产品 #6

**问题**：MCP server 是独立 stdio 进程（`server.ts:96`），`withWriteLock`（`JsonRepository.ts:16` 注释自述）是**进程内 promise-chain mutex**，两个进程互不可见。agent 经 MCP 写 `canvases/<id>.json` 的同时用户在前端拖节点 → 后写覆盖前写 → 节点/边静默丢失。

比 tasks 更严重：画布场景里 agent 和用户**同时操作**是核心卖点，不是边缘情况。

**决策**：
- ✅ **MCP 写收口到 HTTP API**（`http://localhost:PORT/api/canvas/...`），MCP 只经 HTTP 调用，复用 HTTP 进程内的 `withWriteLock`。MCP 直读文件（只读安全）。
- ❌ 不引入文件锁（`proper-lockfile` 增加复杂度）
- 这与现有"MCP→watcher→前端"同步模型一致

### S2. dagre 后端没装 + 前端已主动弃用 —— 双重错误

**提出者**：后端架构师 #4、技术负责人 🔴-2（交叉印证）

**事实**：
- `@dagrejs/dagre ^3.1.1` 只在 `frontend/package.json`，backend **没有**
- `layout.ts:2-5` 注释明确"自定义 DFS，**替代 dagre**——dagre 不保证同级节点顺序"
- 后端引入 dagre 会形成前后端两套不一致的布局算法

**决策**：
- ✅ **`layout.ts` 的 DFS 布局逻辑抽到 `shared/`，前端/后端/MCP 共用**
- ❌ 后端不引入 dagre
- MCP `create_canvas` 的 layout=LR/TB 复用 shared 布局函数

### S3. `data.kind` 与 `node.type` 双重判别 —— 违反 KISS

**提出者**：技术负责人 🔴-4、前端维度三

**问题**：`node.type` 是 React Flow 天然的渲染判别 tag（决定渲染哪个组件），再在 `data.kind` 放一个语义几乎相同的字段是冗余。`type='mindmap'`（text）+ `kind='text'` = 同一节点两个标识。

**决策**：
- ✅ **砍掉 `data.kind`，统一用 `node.type` 判别**
- 旧文档 `type='mindmap'` 在 nodeTypes 里映射 `MindmapNode`（text 行为）
- 新建 text 节点继续用 `type='mindmap'`（兼容旧文档）
- image/link/group 用 `type='image'/'link'/'group'`

### S4. per-doc 迁移是破坏性变更，无回滚方案 —— 最高数据安全风险

**提出者**：技术负责人 🔴-3、后端架构师 #5/#6、产品 #16

**问题**：per-doc 分片在 P0 做是破坏性的。旧 `mindmaps.json`（`{documents:[]}`）拆到 `canvases/<id>.json`，迁移中途崩溃无回滚，`index.json` 与 per-doc 文件无跨文件一致性保证。

**决策**：
- ✅ **per-doc 降级到 P2**（YAGNI——单文件够用，图片是 URL 引用不内嵌，体积增长有限）
- P0 仅加 `schemaVersion` + 新字段（加字段非破坏）
- 若将来做 per-doc：读时迁移 + 旧文件保留备份 + 幂等可重跑 + 迁移回归测试

### S5. "后端零改动"表述错误 —— 误导排期

**提出者**：技术负责人 🔴-1

**问题**：第一章写"后端零改动，全部是前端任务"，但第十章文件清单列了 7 个后端新增文件（JsonCanvasRepository/CanvasService/canvasRoutes/9 个 MCP 工具/CanvasFileWatcher/canvasExport/dataDir 改动）。

**决策**：
- ✅ 修正表述为"**聚合根 MindmapDoc 零改动，新增独立的 canvas 应用层/持久化/MCP/HTTP 子模块**"

### S6. `create_canvas` 节点引用语法空白 —— 工具无法落地

**提出者**：后端架构师 #9

**问题**：`nodes:[{label,kind?}]` 不让 agent 传 id，那 `edges` 的 `from`/`to` 引用什么？后端生成 id 后 agent 写的 `from:"节点1"` 无法对应。

**决策**：
- ✅ **nodes 支持可选 `id`**（agent 可传人类可读临时 id 如 `n1`，不传则后端生成）
- edges 的 `from`/`to` 用该 id
- 写进 MCP 工具的 schema description（agent 靠 description 理解用法）

### S7. 并发乐观锁缺失 —— agent 写入覆盖用户编辑

**提出者**：产品 #6、后端架构师 #8

**问题**：per-doc 存储有 `version` 字段但通篇没说怎么用。agent 通过 MCP 写文件 → watcher 推前端 → 用户未保存编辑被覆盖。

**决策**（与 S1 联动）：
- ✅ MCP 写收口 HTTP 后，复用 HTTP 进程的 `withWriteLock` + 乐观锁
- ✅ MCP 工具**不走 expectedVersion**（agent 串行单线程，乐观锁对它无意义反而制造冲突），内部 force update（findById 拿最新 version 再 applyUpdate）
- ✅ 前端检测到外部变更时：若本地 dirty，提示"画布已被 agent 修改"，而非静默覆盖

### S8. 图片/链接节点创建入口完全没设计 —— 用户不知道怎么放图

**提出者**：产品 #1

**问题**：双击只能建 text，image/link 怎么创建文档没说。竞品全是拖拽创建。

**决策**：
- ✅ P1 补**拖拽创建**（`onDrop` → 判断 dataTransfer → 建 image/link 节点）
- 图片：拖文件 / Ctrl+V 粘贴剪贴板 / 拖网页图片
- 链接：拖 URL / 拖选中文本
- 右键菜单兜底入口

### S9. 对齐辅助线应升 P0 —— 文档自证"解决 80% 排版"

**提出者**：产品 #2、前端维度二

**问题**：文档 13.2 自己说"投入产出比最高、解决 80% 排版"，却标 P1。P0 交付后用户双击建 5 节点就发现对不齐。树形有 dagre 兜底，自由画布**没有自动布局兜底**，对齐线是唯一排版支撑。

**决策**：
- ✅ **对齐辅助线升 P0**（基础 6 线，~75 行）
- gap 等距吸附留 P2（额外 40-60 行）

### S10. 框选前提缺失 —— align/distribute 无法触发

**提出者**：前端遗漏项 #2

**问题**：现有 `<ReactFlow>` 无 `selectionOnDrag`/`panOnDrag` 配置，默认 `panOnDrag=true`（左键拖=平移），框选无法触发 → 13.5 排列工具的前提不成立。

**决策**：
- ✅ 设 `selectionOnDrag` 或 `panOnDrag={[1,2]}`（中键/右键平移）
- `multiSelectionKeyCode` 默认 Meta/Ctrl 确认符合预期

### S11. `FloatingConnectionLine` 是自写组件非内置 —— 文件清单遗漏

**提出者**：前端维度一

**问题**：文档多处提"配 FloatingConnectionLine"措辞像内置组件，实际是官方示例里用户自写的。第十章文件清单漏列。

**决策**：
- ✅ 补 `FloatingConnectionLine.tsx` 到文件清单（需自写，内部 `useStore(s => s.connectionStartHandle)` + `getEdgeParams`）
- `getEdgeParams` 出口加 `measured` 空值兜底（新建节点首帧 NaN）

### S12. 树形操作与自由画布语义冲突 —— Delete 删子树 bug

**提出者**：前端维度六

**问题**：`useMindmapActions` 的 `deleteNode`（172 行）按"删子树"语义（递归删后代），自由画布应"只删单节点 + 连带边"。硬塞一个 context → "自由画布按 Delete 删了一大片"。

**决策**：
- ✅ 按文档模式分流操作 context：树形用 `useMindmapActions`，自由画布用新 `useCanvasActions`（删单节点、无层级）
- 样式/排列/对齐走独立 hook

## 🟡 建议改进（共 14 项）

### B1. 画布内搜索缺失（产品 #3）
- 画布一大就废——Ctrl+F 高亮匹配节点 + 跳转聚焦
- **升 P1**

### B2. MiniMap/导航缺失（产品 #4）
- 自由画布比树形更容易铺得大，无缩略图会迷路
- React Flow 内置 `<MiniMap>` 零成本，**补回 P0**

### B3. 键盘交互体系空白（产品 #5、前端遗漏 #4）
- 删连线/复制粘贴/方向键移动/全选/Esc/手型工具/适应内容 都没说
- 撤销重做粒度（拖动=1步事务、输入=1步、批量增删=1步）
- **补完整快捷键表**

### B4. 5 语义色不够分类（产品 #10）
- primary/destructive/muted 带语义负担，用户做"技术/产品/运营"分类时语义全乱
- **补 shadcn `--chart-1~5` 中性分类色**（Tailwind 数据可视化色，与 shadcn 同源）

### B5. P1 工时严重低估（技术 🟡-6、后端 #6）
- 文档估 5-6h，实际 10-12h
- **拆 P1a（前端：节点+样式+对齐）+ P1b（后端：MCP+导出导入）可并行**

### B6. zip 库未选型 + 无 zip bomb 防护（技术 🟡-7、后端 #10）
- backend 无任何 zip 库
- **选 adm-zip，assets 强制 `<hash>.<ext>` 文件名**（避免中文乱码）
- 导入校验：总字节上限 + 文件数上限 + 路径穿越防护

### B7. MCP 工具 P1 先做 6 个核心（技术 🟡-8）
- `list_canvases` + `read_canvas`(summary) + `create_canvas` + `update_canvas_node` + `connect_canvas_nodes` + `delete_canvas_node`
- mermaid/snapshot 降 P2

### B8. schemaVersion 需迁移机制（后端 #5、产品 #17）
- 只有版本号等于没版本化
- **定义 `MIGRATIONS` 数组 + `applyMigrations(doc)` 在 repository fromJSON 调用**

### B9. assets hash 语义不成立（后端 #3）
- `uploadRoutes.ts:32` 用 `randomBytes` 不是内容 hash，"天然去重"零效果
- **二选一**：上传改内容 hash 命名（真去重）；或文档去掉"天然去重"表述

### B10. branch 8 色与 style.fill 共存渲染优先级未定义（技术 🟡-9）
- 明确 `style.fill > branch > default` 优先级

### B11. 长文本节点场景没覆盖（产品 #7）
- max-width 280 写不下一段想法（Heptabase 核心用例）
- **设计节点高度自适应 + 双击展开编辑模式**，或新增 note 长文本卡片类型

### B12. 模式切换认知混乱（产品 #9）
- 一个文档到底是思维导图还是画布？无显式 mode
- **加 `docMode: 'tree' | 'canvas'` 字段**，或激进合并为一种（都是 canvas，树形只是布局选项）

### B13. 嵌入/引用能力缺失（产品 #8）
- ai-task-flow 定位是工作台，但节点不能嵌入任务卡/其他画布/知识库
- **文档预留 `embed` 节点类型演进方向**

### B14. 感知验证 screenshot 应升 P1（产品 #12）
- agent 盲建 → 文字溢出/节点重叠/连线乱穿
- `get_canvas_screenshot` 直接决定 agent 输出质量
